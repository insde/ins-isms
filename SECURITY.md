# Security Policy

## Scope & Non-Commercial Maintenance Status

This Information Security Management System (ISMS) software is originally developed for internal use and is shared publicly as Free and Open-Source Software under the **GPL** without commercial intent.

Because this project is maintained strictly on a non-commercial, best-effort basis:
* **No Supported Versions / SLAs:** We do not guarantee ongoing maintenance, backports, or fixed timelines for security patches for third-party deployments.
* **Self-Responsibility:** Organizations deploying this software in production are solely responsible for assessing its security, applying updates at their own discretion, and ensuring compliance with their regulatory requirements (e.g., ISO 27001, NIS2, EU CRA).

## Reporting a Vulnerability

We appreciate responsible disclosure from the security community. If you discover a security vulnerability in this codebase, **please do not open a public GitHub issue**.

Instead, please report it privately via one of the following channels:
* **GitHub Private Vulnerability Reporting:** Use the *"Report a vulnerability"* button under the **Security** tab of this repository *(recommended)*.
* **Email:** Send an encrypted or plain-text report to **security@ins.de** with the subject line `[SECURITY] Vulnerability Report - <Brief Description>`.

### What to Include
To help us understand and reproduce the issue efficiently, please include:
* A clear description of the vulnerability and its potential impact.
* Step-by-step instructions or a proof-of-concept (PoC) to reproduce the issue.
* The commit hash, branch, or release tag affected.

## What to Expect

1. **Acknowledgment:** We aim to acknowledge receipt of your report within **7–14 days**, depending on internal capacity.
2. **Evaluation & Remediation:** We will evaluate the issue primarily based on its relevance to our own internal deployment and general codebase health. While we strive to address valid security flaws, **we make no commitment to develop or release a fix**.
3. **Coordinated Disclosure:** Please allow us reasonable time to assess the report before disclosing the vulnerability publicly. We will notify you if and when a patch is merged or if we decide not to pursue a fix, so you can coordinate public disclosure accordingly.
4. **No Bug Bounty:** Please note that we do not operate a paid bug bounty program.
